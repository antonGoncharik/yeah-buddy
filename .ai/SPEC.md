# Yeah Buddy

Telegram Mini App: дневник питания и тренировок в одном приложении.

Питание — своя база продуктов, дни, приёмы, БЖУ. Зал — шаблоны по кругу, сессии, макроциклы с фазами, рабочие веса от максимума. Связь через дату: начатая тренировка помечает день питания как тренировочный. Вид спорта не зашит: очередь, упражнения и еду собирает пользователь.

Интерфейс мобильный, русский.

---

## 1. Стек и границы

```text
Telegram Mini App + бот (grammY)
Next.js App Router (TypeScript, React)
Tailwind CSS + shadcn/ui
Supabase Postgres
jose — сессия
@twa-dev/sdk — WebApp
date-fns, zod, lucide-react
@dnd-kit — порядок шаблонов в круге
```

Клиент в Supabase не ходит. Все чтения и записи — через серверные API Next.js и service role key.

RLS на таблицах включён. Политик для anon нет: доступ только с сервера.

## 2. Окружение

```env
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
TELEGRAM_BOT_TOKEN=
SESSION_SECRET=
NEXT_PUBLIC_APP_URL=
TELEGRAM_MINI_APP_URL=
GEMINI_API_KEY=
GEMINI_MODEL=
```

`SESSION_SECRET` — не короче 32 символов.

`TELEGRAM_MINI_APP_URL` или `NEXT_PUBLIC_APP_URL` — HTTPS URL Mini App для кнопки бота. Без HTTPS кнопка не ставится.

`GEMINI_API_KEY` — необязательный. Без него `/settings/review` показывает только посчитанные факты. `GEMINI_MODEL` по умолчанию `gemini-3.5-flash`.

На сервере: `SUPABASE_SERVICE_ROLE_KEY`, `TELEGRAM_BOT_TOKEN`, `GEMINI_API_KEY`. В клиентский бандл не класть.

## 3. Авторизация

1. Mini App вызывает `Telegram.WebApp.ready()`, `expand()` и при Bot API 8.0+ `requestFullscreen()`.
2. `POST /api/auth/telegram` с `{ initData }`.
3. Сервер проверяет HMAC `initData` (окно 24 часа).
4. Upsert `users` по `telegram_id`, при первом входе — `user_settings`.
5. `ensureInitialData`: стартовые продукты, шаблоны еды, упражнения. Очередь зала не сидится.
6. HTTP-only cookie `session` (JWT jose, 7 дней, `sameSite=lax`, `secure` в production).
7. Если `user_settings.onboarding_completed_at` пустой — редирект на `/onboarding`. Нижней панели там нет. Повтор из настроек: `/onboarding?again=1`. У кого уже есть дни еды или сессии зала, миграция ставит дату и мастер не показывает.

Вне Telegram: «Открой приложение через Telegram-бота.»

В development без `initData`: `POST /api/auth/dev` (в production 404).

## 4. Навигация и экраны

Нижняя панель — три вкладки:

```text
Сегодня      /today
Тренировки   /workouts
Настройки    /settings
```

Продукты — не вкладка. Живут под Настройками: `/foods`, `/food/new`, `/food/[id]`. Вкладка «Настройки» подсвечивается и на этих путях.

`/` редиректит на `/today`. Первый вход без пройденного онбординга — `/onboarding`.

Онбординг — короткий мастер, не тур по экранам:

```text
белок на день — можно пропустить («Пока без еды»)
очередь: программа (один день / сила / всё тело / верх-низ / жим-тяга-ноги) или соберу сам (зал не ведёшь — соберу сам)
веса, если выбрана готовая программа и нет текущей фазы
```

Еда и зал не зависят друг от друга: можно вести только одно. Пустые веса можно оставить. Цифра — рабочий вес для схемы подходов, не обязательно максимум на раз. Повтор из Настроек не меняет очередь. Дату прохождения пишет `user_settings.onboarding_completed_at`.

### Питание

/today/history                      история еды: среднее, бары БЖУ
/today/meals/[mealId]/add           выбор продукта

/today/items/[itemId]               правка граммов
/foods                              список продуктов
/food/new                           новый продукт
/food/[id]                          правка / удаление
/settings                           тема и цели БЖУ сверху. Ниже: еда (продукты, шаблоны, история), зал (очередь, схема, макроцикл), разбор, повтор онбординга
/onboarding                         первый вход; `?again=1` — повтор из настроек, очередь не меняет
/settings/meals                     шаблоны дня отдыха и тренировки
/settings/meals/[dayType]           состав шаблона: приёмы, граммы

Тема: светлая / тёмная, cookie, цвет шапки Telegram. Тип дня подкрашивает фон и карточки: отдых — шалфей, тренировка — тёплый уголёк. Акцент кнопок остаётся ржавым.

## 5. Питание

### Продукты

Только своя база. Внешних каталогов, штрихкодов, импорта нет.

Поля в базе: название, бренд, состояние, БЖУ и ккал на 100 г, стандартная порция (граммы + подпись), избранное, заметки. Форма показывает название, БЖУ на 100 г, порцию в граммах и избранное; бренд, подпись порции и заметки не трогает. На карточке один пример: творог 5% — 17 / 5 / 2, 150 г.

Состояния:

```text
raw      сырой
dry      сухой
cooked   приготовленный
as_is    как есть
liquid   жидкий
```

БЖУ хранятся на 100 г. Порция:

```text
макро = макро_на_100 × граммы / 100
ккал  = ккал_на_100 × граммы / 100
```

Если ккал не указали при создании: `белки×4 + жиры×9 + углеводы×4`.

Экран: 1 знак у БЖУ, ккал целые.

Список: поиск по имени и бренду, фильтры Все / Избранное / Недавние. Недавние — уникальные `food_id` из последних `meal_items`. Добавление, правка, удаление, избранное.

Удаление продукта не ломает старые дни: в `meal_items.food_id` — `on delete set null`, снапшот остаётся.

### Приёмы

```text
breakfast      Завтрак
lunch          Обед
snack          Полдник
pre_workout    До тренировки
post_workout   После тренировки
dinner         Ужин
```

Порядок: завтрак → обед → полдник → до → после → ужин (`sort_order` 10…60).

На экране дня:

- отдых — без «до/после тренировки»;
- тренировка — без полдника.

В БД все шесть приёмов создаются всегда.

### День

Один день на пользователя: `unique(user_id, date)`.

Тип: отдых / тренировка (`is_training_day`). Цели БЖУ копируются из `user_settings` в момент создания или смены типа. Старые дни от смены настроек не пересчитываются.

Пустой день:

```text
Отдых
Тренировка
Как вчера
```

Создание берёт шаблон еды того же типа (`meal_templates.day_type`). Нет шаблона — пустые приёмы.

Копирование вчера: тип, цели, приёмы, снапшоты. Если день уже есть — подтверждение замены.

Смена типа на экране дня переписывает цели из текущих настроек. Править можно только календарное «сегодня»: стрелки на прошлые дни — просмотр, без Отдых/Тренировка, «Как вчера», шаблона дня и правки приёмов. Будущие даты на этом экране отсекаются.

Сводка: крупно оставшиеся ккал, под ними оставшийся белок; ниже бары БЖУ.

### Снапшоты

Каждая позиция в приёме хранит имя, граммы, БЖУ порции и `per_100_snapshot`. Правка продукта не меняет прошлые записи.

### Цели по умолчанию

Отдых: 120 / 70 / 200. Тренировка: 120 / 70 / 250. Ккал = Б×4 + Ж×9 + У×4 (в `days.target_kcal` — generated column). Уже созданные настройки пользователя не переписываются.

### Шаблоны еды

Два шаблона: «День отдыха», «День тренировки». Экран в настройках: `/settings/meals`. Пользователь правит состав приёмов и граммы. Макросы в шаблоне считаются от текущих значений продукта: это рецепт, не снапшот.

Сидовые продукты и стартовый состав — `src/lib/seed.ts`. Обычные продукты (курица, яйца, крупы, творог, фрукты), без брендов. В избранном — те, что в шаблоне. Имена с уточнением состояния, например «Овсянка сухая», «Куриное филе сырое». Сид шаблона пишется только при первом создании; пустой или изменённый шаблон при следующем входе не затирается.

Правка шаблона не трогает уже созданные дни. Новый день копирует текущий состав. Шаблон правится в Настройках, не с экрана дня.

### История еды

`/today/history`: дни с фактом и планом, бары БЖУ, среднее по загруженным (окно до 7), группировка по месяцам. День открывается как `/today?date=&view=history` — только просмотр, без правки граммов, типа дня и состава. Стрелки на `/today?date=` тоже только просмотр: прошлый день нельзя править с главного экрана.

### Добавление в приём

Избранное / недавние / все / поиск / новый продукт → граммы. Быстрые: 10, 50, 100, 150, 200, 250, 300, 400 и стандартная порция.

## 6. Тренировки

Модель продукта — **шаблоны и круг**, не календарь ПН/СР/ПТ.

### Упражнения

Справочник пользователя. В UI один список рабочих упражнений, без вкладки архива. В БД `is_active` / `archived_at` остаются: упражнение не удаляют, чтобы не ломать историю сессий и максимумов. Из интерфейса архивировать нельзя.

Поля: имя, короткое имя, категория, тип (динамика / статика / оба), единица, шаг веса `1 | 2.5 | 5`, пресет разминки, опциональный слот.

Категории: `base` / `isolation`. В форме база или изоляция, для любого типа (динамика / статика / оба). В стартовом сиде изоляции нет.

Пресет разминки:

```text
barbell   штанга     50×5 / 70×3 / 80×1
cable     блок       50×5 / 70×3
none      не в план  упражнение не попадает в автоплан сессии
```

Рабочие проценты пресет не меняет. Статика: разминка — тот же пресет (повторы), рабочие — удержания. Сброс — без разминки.

При создании задаётся начальный глобальный максимум. Понизить глобальный рекорд формой нельзя. Фазовый максимум правится на экране макроцикла.

### Шаблоны и круг

Шаблон: имя, вид (`dynamic` | `static`), `sort_order`, `is_active`, упорядоченный список упражнений.

Круг = активные шаблоны по `sort_order`.

Сид пишется только в пустой справочник упражнений. Очередь (шаблоны дней) не сидится: её ставит онбординг или экран очереди готовой программой, либо пользователь собирает сам. Уже существующие упражнения и шаблоны не дополняются и не переименовываются. Максимумы не сидятся.

Готовые программы (не сид, ставятся по выбору):

```text
Один день    Зал                 одна тренировка, самый простой старт
Сила         Сила A / Сила B     присед каждый раз, жим и тяга
Всё тело     Тело A / Тело B     два разных дня на всё тело
Верх / Низ   верх, низ
Жим / Тяга / Ноги   жим, тяга, ноги с подсобкой
```

Слот упражнения в БД остаётся, в рантайме состав сессии берётся из шаблона, не из слота. Готовая программа создаёт или обновляет дни по имени и включает их в очередь; остальные дни выключает, не удаляет.

Следующий шаблон: после последней не пропущенной сессии текущей фазы (без фазы — после последней сессии с `template_id`). GET хаба сессию не создаёт.

Пропуск в круге: «Не это — взять следующую» пишет id в `workout_settings.skip_template_ids`. Дату не занимает. «Вернуть в круг» снимает последний пропуск. После выполненной сессии список пропусков очищается.

Пользователь может начать не следующий шаблон — с подтверждением.

На хабе в очереди: шаблон сегодняшней сессии — «сегодня»; следующий в круге — «дальше». Если сессия уже есть, имена не кнопки.

### Сессии

Одна тренировка зала на дату: `unique(user_id, session_date)`.

Зал создаётся только по кнопке «Начать» (хаб, сегодня). Если ни одно упражнение шаблона не имеет максимума и пресета ≠ `none`, сессия не создаётся: на хабе ссылка на упражнения, `POST /api/sessions` отвечает 400. Макроцикл и фаза подставляются, если есть; без макро — `macro_cycle_id` и `phase_id` пустые, веса как в рабочей схеме от глобального максимума.

Статусы: `planned` | `completed` | `skipped`. UI создаёт `planned`, завершает в `completed`. Не начатую сессию «Не получилось сегодня» **удаляет**, не помечает skipped. Статус `skipped` в схеме есть, продуктовый поток его не ставит.

План упражнений (зал): из шаблона, только с максимумом фазы или глобальным и пресетом ≠ `none`. В зале можно добавить упражнение на сегодня («Добавить упражнение»). Состав без шаблона не набирается. Единица подхода — у самого сета: `planned_reps` или `planned_seconds`. Статика: разминка в повторах (как динамика), рабочие — удержания в секундах.

Экран сессии зала — шпаргалка и дневник:

- короткая подсказка: «Не так — нажми подход. В конце Готово»;
- разминка свёрнута, можно открыть;
- рабочие тоже можно свернуть, чтобы занимали меньше места;
- тап по подходу — правка веса / повторов / секунд этого подхода;
- на удержании (секунды) кнопка «Засечь» считает вниз, факт сама не пишет;
- заметка (как прошло);
- «Готово» копирует план в факт по всем подходам (с учётом правок). Подход за подходом не подтверждают. После записи больше ничего делать не нужно. Главное действие на длинных экранах (сессия, схема, макро, списки) — липкая кнопка снизу, не только в хвосте списка.
- после завершения, если факт уехал от плана — виден план; если вес выше плана — необязательная ссылка на максимумы.

После завершения зала: ссылка на следующий шаблон круга; если в фазе набран полный круг — намёк закрыть фазу (сам не закроется).

История: `/workouts/history` и блок на хабе (последние completed зала). Строка — имя шаблона и факт рабочих (не только дата). Сделанную сессию можно поправить: «Поправить записанное» открывает те же подходы, статус остаётся completed.

### Макроциклы и фазы

Макро необязателен. Без него круг работает, схема весов — `formulas.dynamic.base` / `static.base`. На хабе блок макроцикла только если он уже заведён. Завести — из Настроек, и только если в схеме есть фазы (`formulas.cycle`).

Фазы задаёт пользователь в схеме (продвинутый блок). Готовые циклы: **Разгон → сброс** (`ramp` → `volume` → `peak` → `deload`) и **Нагрузка / разгрузка**. Можно добавить свои фазы, переименовать, поменять порядок, отметить «без разминки» и «поднять веса в конце».

Личный цикл разгон–набор–рывок–сброс не сидится новым пользователям. Уже сохранённая схема с разными рабочими в разгоне/наборе/рывке читается как этот цикл.

Один текущий макроцикл и одна текущая фаза на пользователя.

Переход фазы — руками на `/workouts/macro`. Круг фазу не закрывает. После числа completed-сессий ≥ размера круга подсказка: первый круг — фазу можно держать дальше; закрытие всегда руками.

Переходы максимумов считает `cycle`: копировать, либо `+max_increase_percent` если у закрываемой фазы `increase_on_end`. Последняя фаза закрывает макро, следующий номер начинается с первой фазы цикла; максимумы с последней тяжёлой фазы (`skip_warmup = false`).

Пользователь правит предложенные числа до подтверждения. `phase_maxes` только дополняются; текущий = последняя строка по `(phase_id, exercise_id)`.

Глобальный рекорд (`global_maxes`) пишется при создании упражнения и если новый фазовый максимум больше текущего. С рабочего сета ~88% не обновляется.

После закрытого макро — карточка recap: прирост максимумов первая фаза → последняя тяжёлая.

### Формулы весов

Как в коде `src/lib/workout/default-formulas.ts` и `formulas.ts`.

```text
вес = FLOOR(максимум × процент / 100, шаг_упражнения)
```

FLOOR вниз, не к ближайшему. Шаг на упражнении.

План сессии считается от схемы в `workout_settings.formulas`. Её правит экран `/settings/formulas`. Без макроцикла — `base`. С фазой — `phases[key]` или `base`. Разминка не ставится, если у фазы `skip_warmup`. Для перехода с приростом — `max_increase_percent` (дефолт 5). Шаг веса — на упражнении, не глобальный.

Новому пользователю пишется схема **3×5** без фаз. Уже сохранённая схема не переписывается. Готовые рабочие: 3×5, 5×5, 3×8, пирамида. Готовые циклы — отдельно, в блоке фаз. Личная 88×3 / 82×5 / 76×7 в сид и в готовые рабочие не входит; если уже сохранена — читается как цикл разгон → сброс.

```text
3×5         80%×5 три раза
5×5         80%×5 пять раз
3×8         70%×8 три раза
пирамида    80×5 / 75×6 / 70×8
```

Статика без цикла: рабочие 115%×6с три раза. Лёгкая фаза цикла: динамика 60%×5×3, статика 50%×3с два раза, без разминки.

Пример, максимум 220, шаг 2.5, динамика 3×5, пресет штанга:

```text
Разминка: 110×5 / 152.5×3 / 175×1
Рабочие:  175×5 / 175×5 / 175×5
```

На экране схемы пример после прироста считает килограммы от уже поднятого максимума (`max_increase_percent`). Фазы без прироста — от введённого.

Статика, максимум 76, шаг 1, пресет блок:

```text
Разминка: 38×5 / 60×3
Рабочие:  87×6с / 87×6с / 87×6с
```

Один максимум фазы на упражнение для динамики и статики.

### Прогресс

`/workouts/progress`: кривые по упражнениям. Точки — фактические рабочие из completed-сессий зала (первый рабочий подход). Нет факта — максимумы фаз, иначе глобальные. Фильтр все / база / изоляция. Среднее изменение с первых точек.

## 7. Связь еда ↔ зал

Общий ключ — календарная дата.

Старт сессии зала: если день питания на эту дату уже есть и он отдых — сервер ставит тренировочный тип и цели зала. День питания сам не создаётся.

Баннер на «Сегодня»: если есть зал — ссылка на запись (и на отдыхе тоже). Если зала ещё нет, на сегодняшней дате видна очередь: имя следующего шаблона и «Начать», даже на пустом дне и на отдыхе.

Тип дня питания пользователь может переключить вручную независимо от зала.

## 8. Кэш last-known

`src/lib/api-cache.ts`: GET-ответы в `localStorage` (`yb.v1:`). Сначала показать кэш, потом сеть. Если сеть упала и кэш есть — остаться на кэше, экран рабочий. Это не offline-first: новые записи без сети не ставятся в очередь, service worker нет.

## 9. Бот и Mini App

Бот: только `/start`. Текст — это дневник, не программа тренера. Кнопка «Открыть дневник» (webApp).

Webhook: `POST /api/telegram/webhook`.

Уведомлений, рассылок, Stars нет.

Mini App: `ready` + `expand` + `requestFullscreen` (8.0+), авторизация `initData`, иначе экран «через бота».

Разбор живёт только в Mini App (`/settings/review`): код считает бриф (средние БЖУ, попадания, топ продуктов, план vs факт, фаза, рабочие веса). Текст пишется только по брифу. Сырые приёмы и подходы в модель не идут, кроме топа продуктов и коротких заметок сессий. С хаба зала ссылок на разбор и схему подходов нет — только из Настроек. На экране модель не называется.

```text
GET  /api/ai/review?days=14|30
POST /api/ai/review            { days: 14 | 30 }
```

Не совет врача, не новая программа, не смена формул.

## 10. Схема

Миграции по порядку:

```text
supabase/migrations/0001_init.sql              users, settings, foods, days, meals, meal_items, meal_templates
supabase/migrations/0002_exercises.sql         workout_settings, exercises, global_maxes
supabase/migrations/0003_macro_cycles.sql      macro_cycles, workout_phases, phase_maxes
supabase/migrations/0004_sessions.sql          workout_sessions
supabase/migrations/0005_sets.sql              session_exercises, workout_sets
supabase/migrations/0006_templates.sql         workout_templates, template_exercises; template_id на сессии
supabase/migrations/0007_session_kind.sql      kind gym|table; unique (user_id, session_date, kind)
supabase/migrations/0008_neutral_defaults.sql  дефолтные цели БЖУ для новых пользователей
supabase/migrations/0009_onboarding.sql        onboarding_completed_at; дневники с историей помечаются пройденными
supabase/migrations/0010_exercise_categories.sql  категория только base|isolation; armwrestling → base
supabase/migrations/0011_drop_session_kind.sql kind убран; одна сессия на дату
supabase/migrations/0012_skip_template_ids.sql skip_template_ids колонка, не jsonb формул
```

Актуальная схема — сумма этих файлов, не один `0001`.

### Питание

`users` — `telegram_id` уникален.

`user_settings` — цели отдыха и тренировки, `onboarding_completed_at`.

`foods` — продукты пользователя.

`days` — дата, `is_training_day`, цели; `target_kcal` generated.

`meals` — `meal_type`, `sort_order`; unique `(day_id, meal_type)`.

`meal_items` — снапшот + `food_id` nullable.

`meal_templates` / `meal_template_items` — шаблоны дня отдыха и тренировки, правка в `/settings/meals`.

### Зал

`exercises` — архив через `is_active` / `archived_at`.

`global_maxes` — история рекордов, строки не обновляются.

`macro_cycles` — номер, статус current/completed; один current на пользователя.

`workout_phases` — `phase_type` свободная строка (ключ фазы), необязательное `name`, `sort_order > 0`; одна current на пользователя.

`phase_maxes` — append-only.

`workout_templates` / `workout_template_exercises` — круг и состав.

`workout_sessions` — дата, вид, `template_id`, nullable макро/фаза. Одна сессия на дату.

`session_exercises` / `workout_sets` — план и факт отдельно (`planned_*` / `actual_*`).

`workout_settings` — `max_increase_percent`, jsonb `formulas` (`base`, `phases`, `cycle`, `warmups`), `skip_template_ids`.

`exercises.slot` (`a`/`b`/`c`) — наследие; состав дня из шаблона. Форма упражнения слот не показывает.

## 12. Правила, которые остаются в силе

1. Только своя база продуктов. Нет внешних API, краулера, штрихкодов, Open Food Facts и импорта.
2. База только с сервера. Секреты не в клиенте.
3. Снапшоты в `meal_items`. Правка продукта не пересчитывает историю.
4. Упражнения не удалять. История сессий и максимумов — дневник, не затирать. В UI архива нет.
5. `phase_maxes` и `global_maxes` дополнять, не UPDATE текущей строки.
6. Состав сессии зала — шаблон. Круг — `sort_order` активных шаблонов.
7. Сессия не создаётся молча при GET. На дату: один зал.
8. Веса: FLOOR до шага упражнения. План и факт раздельно. История и прогресс читают факт рабочих.
9. На сессии зала одна кнопка «Готово». Можно добавить упражнение и заметку.
10. UI русский, мобильный.
11. Кэш last-known — показывать сразу; полный offline-first не делать.
12. Шаблоны еды правит экран `/settings/meals`. Сид не затирает уже существующий шаблон. Очередь зала не сидится; готовая программа не удаляет чужие дни, только выключает.
13. Разбор: цифры считает код. Модель не пересчитывает БЖУ и веса и не выдумывает записи.
